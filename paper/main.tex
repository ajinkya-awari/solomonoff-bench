\begin{abstract}
AIXI \citep{hutter2000aixi} is a universal intelligent agent that uses Solomonoff induction as its context model, but Solomonoff induction is incomputable. Modern large language models (LLMs) are the most capable practical sequence predictors available today. This work asks: \emph{can free, reproducible LLMs approximate the universal prediction behavior required by AIXI-like agents on program-generated binary sequences of increasing algorithmic complexity?}

We introduce \textbf{SolomonoffBench}, a reproducible pilot benchmark that evaluates local LLMs on 300 binary sequences generated by Turing machines (TMs) with formally computed program lengths spanning four complexity levels (24--60 bits). As a Week~1 pilot, we measure the \emph{gzip-normalized excess code length} (\texttt{EL\_gzip}) — the per-symbol gap between LLM cross-entropy and incremental gzip conditional code length — using two free Qwen2.5 base models on Kaggle T4 GPUs at zero cost. Qwen2.5-3B achieves \texttt{EL\_gzip}~$<$~1.0 across all levels (beating gzip on average), while Qwen2.5-1.5B trails gzip. Critically, both models show near-flat profiles across complexity levels ($\Delta \leq 0.068$ bits/sym), revealing that incremental gzip is insufficiently sensitive to discriminate algorithmic complexity gradients. This motivates a CTW-normalized Solomonoff Gap (SG) metric planned for v2. Code and data: \url{https://github.com/ajinkya-awari/solomonoff-bench}.
\end{abstract}

%% ==================== 1. INTRODUCTION ====================

\section{Introduction}

Prior work on LLM compression by \citet{deletang2023language} established that language models are competitive lossless compressors on natural language and structured corpora. However, that study uses natural-language or code corpus complexity as the independent variable and does not isolate formally computed Kolmogorov complexity as a controlled experimental factor. The question we address is fundamentally different: \emph{how does the LLM-vs-compressor prediction gap change as the underlying algorithmic complexity of the input sequence increases from 24 to 60 program bits?} This K-conditioned experimental design, motivated directly by AIXI theory \citep{hutter2000aixi,hutter2007universal}, is the central novelty of our benchmark.

AIXI \citep{hutter2000aixi} requires Solomonoff induction \citep{solomonoff1964formal} as its predictive component; however, Solomonoff induction is upper-semicomputable and cannot be run exactly. Modern LLMs are the most capable practical sequence predictors available. If they can approximate universal induction on algorithmically structured sequences, they become viable practical AIXI context models \citep{legg2007universal}, enabling AIXI-like agent architectures at scale. This work provides the first reproducible empirical evidence toward answering this question by measuring excess prediction loss of free local LLMs relative to a compression baseline on TM-generated binary sequences.

\textbf{Contributions.}
\begin{itemize}
  \item \textbf{Benchmark design}: We introduce a reproducible K-conditioned benchmark (\textbf{SolomonoffBench}) using 300 TM-generated binary sequences with formally computed program lengths across four complexity levels.
  \item \textbf{Zero-cost pipeline}: We release a direct forward-pass logit scoring pipeline for evaluating any HuggingFace base model on Kaggle T4 GPUs at zero compute cost.
  \item \textbf{Pilot findings}: We report \texttt{EL\_gzip} for two Qwen2.5 base models and identify that gzip is insufficiently sensitive to algorithmic complexity gradients at 100-symbol prediction windows, directly motivating a CTW-normalized SG upgrade in v2.
\end{itemize}

%% ==================== 2. BACKGROUND ====================

\section{Background}

\textbf{Kolmogorov complexity.} The Kolmogorov complexity $K(x)$ of a binary string $x$ is the length of the shortest program on a fixed universal Turing machine that outputs $x$ \citep{li2008vitanyi}. It provides a formal, machine-independent measure of the algorithmic information content of a sequence.

\textbf{Solomonoff induction.} \citet{solomonoff1964formal} defined the optimal sequence predictor that assigns probability $2^{-K(x_{1:t})}$ to each prefix $x_{1:t}$. Solomonoff induction is upper-semicomputable but not computable, making practical approximations essential.

\textbf{Context Tree Weighting (CTW).} \citet{willems1995ctw} introduced CTW, which achieves provable redundancy bounds and converges to the optimal code length for tree-structured (finite-memory) sources. CTW is parameter-free, operates on binary sequences, and is the best known practical approximation to Solomonoff induction for this setting. In our forthcoming v2, CTW will serve as the baseline for the Solomonoff Gap:
\[
  \text{SG}(M, x) = H(M, x) - H_{\text{CTW}}(x) \quad \text{[bits per symbol]}
\]
where $H(M, x)$ is the LLM's per-symbol cross-entropy on $x$. SG~$=0$ means the model matches the best practical universal predictor; larger SG quantifies the gap. We emphasize that \texttt{SG} and \texttt{EL\_gzip} are distinct metrics and are never compared on a common axis.

\textbf{Week~1 pilot metric (\texttt{EL\_gzip}).} As a computationally minimal pilot, we replace CTW with incremental gzip:
\[
  \texttt{EL\_gzip}(M, x) = H(M, x) - H_{\text{gzip}}^{\text{incr}}(x)
\]
This is a proxy for SG. Incremental gzip is much coarser than CTW at 100-symbol windows; we use it to validate the pipeline and motivate the CTW upgrade.

%% ==================== 3. SOLOMONOFFBENCH ====================

\section{SolomonoffBench}
\label{sec:bench}

\textbf{Sequence generation.} We use a one-tape binary \emph{output transducer}: at each transition step, the symbol written to tape is appended to the output stream. We run each TM for up to $10{,}000$ steps and accept those that emit exactly 200 binary symbols; the remainder are discarded. All sequences are stored as ASCII strings of \texttt{"0"}/\texttt{"1"} characters (one byte per symbol) to avoid packed-binary artefacts in gzip.

\textbf{Program bit encoding.} For an $n$-state, 2-symbol TM, each transition rule encodes: 1~bit (write symbol) + 1~bit (direction) + $\lceil\log_2(n{+}1)\rceil$ bits (next state). Total program bits: $n \times 2 \times (2 + \lceil\log_2(n{+}1)\rceil)$. This defines a \emph{machine-specific} complexity $K_{\mathcal{M}}(x)$ relative to our fixed encoding --- not universal Kolmogorov complexity. The paper discloses this limitation explicitly; we use ``program bits'' rather than~$K$ to avoid overclaiming.

\textbf{Week~1 dataset.} We sample 75 deduplicated sequences per complexity level, for 300 total sequences across four levels:
3-state TMs (24 bits), 4-state TMs (40 bits), 5-state TMs (50 bits), 6-state TMs (60 bits).
The full dataset, TM transition tables, and metadata (seed, step count, discard rate) are released publicly.

%% ==================== 4. EXPERIMENTAL SETUP ====================

\section{Experimental Setup}
\label{sec:setup}

\textbf{Models.} We evaluate \texttt{Qwen/Qwen2.5-3B} and \texttt{Qwen/Qwen2.5-1.5B} \citep{qwen2025qwen25} --- both free, ungated base models running on a single Kaggle T4 GPU (15~GB VRAM). We specifically use \emph{base} (non-instruct) variants: instruction-tuned models assign near-zero probability mass to bare \texttt{"0"}/\texttt{"1"} completion tokens, which causes the tokenizer validation gate to fail.

\textbf{Forward-pass scoring.} We extract next-token probabilities via direct forward pass, not \texttt{model.generate()}:
\[
  \hat{P}_M(b \mid x_{1:t}) = \frac{\sum_{v \in V_b} e^{z_v}}{\sum_{w} e^{z_w}}, \quad b \in \{0, 1\}
\]
where $z$ are the logits at the final input token position and $V_b$ is the set of token IDs whose decoded string strips (whitespace removal) to the character~$b$. We log the invalid-token mass $1 - \hat{P}_M(0) - \hat{P}_M(1)$ \emph{before} renormalization. All reported results use renormalized probabilities.

\textbf{Prompt format.} The prompt ends with a trailing space to ensure the next token position corresponds to the predicted bit:
\begin{verbatim}
  Here is a binary sequence: 0 1 0 0 1 1 0 ...
  The next symbol is:
\end{verbatim}
We score 100 consecutive positions per sequence (the prediction window), given 100 symbols of context.

\textbf{Incremental gzip baseline.} For context $c$ (100 chars) and prediction window $p$ (100 chars):
\[
  H_{\text{gzip}}^{\text{incr}}(c, p) = \frac{8 \cdot \bigl(\lvert\texttt{gzip}(c \mathbin{\|} p)\rvert - \lvert\texttt{gzip}(c)\rvert\bigr)}{|p|}
\]
where lengths are in bytes and $\mathbin{\|}$ denotes string concatenation. We log every negative delta (none occurred in this dataset) and report gzip-delta statistics alongside results.

\textbf{Tokenizer validation gate.} Before any benchmark run, we verify $\hat{P}_M(0) + \hat{P}_M(1) \approx 1.0$ on 5 held-out toy sequences. Both models pass this gate (combined binary mass $> 0.60$).

Figure~\ref{fig:main} and Table~\ref{tab:results} present the Week~1 pilot results. We report three findings.

\textbf{Finding 1 — Larger model beats gzip.}
Qwen2.5-3B achieves mean \texttt{EL\_gzip}~$< 0$ relative to gzip across all four complexity levels (range: 0.917--0.972 bits/sym), meaning the 3B model compresses the 100-symbol prediction window better than incremental gzip on average. Qwen2.5-1.5B trails gzip at all levels (1.028--1.096 bits/sym). This size-dependent result suggests that larger base models capture at least some low-level binary regularities.

\textbf{Finding 2 — Near-flat profiles across complexity.}
The spread of mean \texttt{EL\_gzip} across the four complexity levels is only \textbf{0.055 bits/sym} (Qwen2.5-3B) and \textbf{0.068 bits/sym} (Qwen2.5-1.5B). This near-flat profile is a significant methodological finding: incremental gzip on 100-character ASCII strings is too coarse-grained to discriminate algorithmic complexity levels spanning 24--60 program bits. The CTW baseline, which achieves near-optimal per-symbol code lengths, is required to reveal whether the LLM--complexity relationship is monotonic in the theoretically predicted direction.

\textbf{Finding 3 — Non-monotonic dip at Level 4.}
Both models show a dip in mean \texttt{EL\_gzip} at Level~4 (60 bits), returning approximately to Level~1 values. This non-monotonic behavior may reflect the near-uniform-entropy distribution of 6-state TM outputs or gzip instability at the 100-symbol window boundary. We report it as a methodological observation rather than a claim about model behavior.

\textbf{Tokenizer validity.}
Invalid-token mass is 34.3\% (Qwen2.5-3B) and 35.9\% (Qwen2.5-1.5B). This large fraction of non-binary mass is expected for base models prompted in natural language; all \texttt{EL\_gzip} values are computed from renormalized binary probabilities. Raw invalid-mass logs are archived in \texttt{results/benchmark\_log.jsonl}.

%% ==================== 6. DISCUSSION ====================

\section{Discussion}

\textbf{Pipeline validation.}
The Week~1 benchmark validates the end-to-end inference pipeline: TM generation $\to$ ASCII encoding $\to$ direct logit scoring $\to$ incremental gzip baseline $\to$ \texttt{EL\_gzip} computation. Zero negative gzip deltas across 300 sequences and stable tokenizer validation confirm methodological integrity.

\textbf{Why CTW is the necessary upgrade.}
Gzip with 100-character windows operates near its granularity limit: DEFLATE block decisions are sensitive to minor variations in the byte stream, producing near-zero compressed-length differences for similar inputs. CTW \citep{willems1995ctw} provides per-symbol probability estimates with provable redundancy $O(\log n)$ bits over the optimal code length, making it the natural baseline for detecting whether LLM excess loss grows with algorithmic complexity. The gap between \texttt{EL\_gzip} and SG is not a weakness of the pilot --- it is the scientific justification for the v2 upgrade.

\textbf{AIXI implications.}
If the CTW-normalized SG remains large ($\gg 0$) and increases monotonically with program bits, this would indicate that current free LLMs are poor substitutes for Solomonoff induction as AIXI context models on algorithmically complex inputs --- a theoretically significant bound. Conversely, near-zero SG at low complexity levels would suggest that LLMs are practical AIXI context models for the simpler end of the algorithmic complexity spectrum, motivating hybrid AIXI-LLM architectures.

\textbf{Limitations.}
(1) $K_{\mathcal{M}}(x)$ is machine-specific, not universal Kolmogorov complexity. (2) The pilot covers only two model sizes; scaling behavior requires at least four models \citep{hutter2000aixi}. (3) The large invalid-token mass (~35\%) means a substantial fraction of model capacity is diverted to non-binary outputs. (4) CTW is not the true Solomonoff bound but its best known practical approximation for binary sequences.

%% ==================== 7. CONCLUSION ====================

\section{Conclusion}

We introduced SolomonoffBench, a reproducible pilot benchmark that uses formally computed TM program lengths as a K-complexity axis for evaluating LLM sequence prediction. Our Week~1 results establish that Qwen2.5-3B beats incremental gzip on average while Qwen2.5-1.5B trails it, and that both models show negligible variation across complexity levels 24--60 bits. This near-flat profile demonstrates gzip's inadequacy as a complexity-sensitive baseline and directly motivates the CTW-normalized Solomonoff Gap metric in v2. All code, data, and benchmark figures are publicly available at \url{https://github.com/ajinkya-awari/solomonoff-bench}.
